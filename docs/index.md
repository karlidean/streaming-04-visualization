## Custom Project

### Dataset

The Kafka producer used the original sales dataset provided with the project. The dataset contains
sales transaction records with fields such as order_id, customer_id, product_id, region_id, quantity,
unit_price, subtotal, tax_amount, and total.

### Kafka Messages

The producer sent individual sales transaction records as Kafka messages to the configured sales topic.
Messages used the existing project structure and were enhanced by the consumer to include a custom
total_tax_collected metric.

### Consumer Processing

The consumer received sales transaction messages from Kafka, validated them, enriched them with
derived fields, and tracked running statistics. Accepted records were written to a CSV file, and the
consumer calculated a cumulative tax collected metric that was logged and visualized during processing.

### Experiments

For a Phase 4 change, I modified the consumer to calculate and track cumulative tax revenue using a
running total of tax_amount values. For a Phase 5 application, I customized the live visualization
and output data to display Cumulative Tax Collected by Message and added the metric to the output CSV.

### Results

When the producer and consumer were executed, sales messages were successfully streamed through Kafka,
validated, enriched, and written to the output file. The consumer displayed running sales statistics
and a live chart showing cumulative tax revenue increasing as messages were processed.

### Interpretation

The custom project extended the original example by introducing a business-focused metric that tracked
total tax revenue over time. Watching messages move through Kafka demonstrated how streaming systems
can provide real-time business intelligence, allowing organizations to monitor revenue trends and
tax collection as transactions occur.
